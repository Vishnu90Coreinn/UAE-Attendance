# S5 Finalise and lock a month implementation plan

> Use superpowers:subagent-driven-development, test-driven-development and verification-before-completion. Scope is the existing approved HANDOVER S5 and master plan R8/R9/C5; the owner requested the next slice and avoidance of unnecessary repeated work.

**Goal:** An Administrator can freeze a monthly payroll, see immutable figures and letterhead, and reopen it with an audited reason; attendance writes cannot cross the finalisation boundary.

**Architecture:** Persist PayrollPeriods and PayrollDetails in one transaction with the audit row. Transaction-owned SQL application locks serialize finalise/reopen (exclusive) against attendance writes and report reads (shared), using the month key and a consistent order: month lock, settings, workers, attendance. The existing report DTO drives screen/print/PDF; finalised reads use stored data only. No new library.

**Baseline:** S4 `e560076`, clean and pushed. Its freshly verified 505 API / 307 web tests and builds are reused as the starting evidence. Use the requested stacked `slice/s5-finalise` branch in the existing clean checkout; avoid an unnecessary duplicate checkout/setup.

## Contract and implementation decisions

- Keep existing report fields. Add nullable `finalisedBy` (username), `finalisedUtc` (ISO UTC); null on Draft.
- `POST /api/payroll/{month}/finalise` takes `{revision}` from the displayed report, returns 200 finalised report. Require the revision to bind confirmation to the visible totals. Missing revision or malformed/future UAE month: 400. Already finalised or stale revision: 409. Administrator only; other roles 403; anonymous 401.
- `DELETE /api/payroll/{month}/finalise` takes `{reason}`, trimmed, required, maximum 500 characters, returns 200 current draft report. Not finalised: 409. Same role matrix.
- PayrollPeriods: unique year/month, company overtime rate applied, finalisation actor/time, and five company letterhead fields copied from the report. Those company columns make the requirement that finalised screen/PDF read only the snapshot explicit. PayrollDetails hold all frozen worker identity, rates and amount fields; FK period cascade and worker restrict, unique period/worker. Monthly aggregate hours/pay need wider precision than daily attendance fields.
- No future-month finalisation, using the UAE business month and existing TimeProvider. Empty reports are allowed, consistent with the current report contract.
- Finalise/reopen audit writes commit atomically. Reopen audit includes trimmed reason, previous totals and finalisation metadata.
- Report hashes include finalisation state/metadata. Finalised PDFs show Finalised and the actor/date; draft wording remains correct. Keep English scope and PdfPig.
- Both attendance batch upsert/clear and DELETE retain their existing in-transaction guard. Replace the stub with a real month lock/check. Read responses expose the existing isFinalised field.
