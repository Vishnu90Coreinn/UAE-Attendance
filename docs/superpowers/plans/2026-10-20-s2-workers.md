# S2 — Worker Directory

**Goal:** HR Staff and Administrators can list, add, edit, deactivate/activate and delete workers; everyone signed in can view them. Payroll settings (overtime rate, company details) exist in the database and are readable through the API.

**Branch:** `slice/s2-workers` (stacked on `slice/s1-sign-in`). **Master plan:** `2026-10-19-hr-payroll-vertical-slices.md` (S2; prototype features W1-W7; decisions C7). **UI rules:** `docs/design-system.md` (ui-ux-pro-max) — mandatory. Same working method as S1: compact spec, test-first implementers, backend and web tasks in parallel (disjoint folders).

## Demo

As HR Staff add a worker (ID pre-filled `EMP-005`), edit the rate, deactivate and re-activate; a duplicate ID is refused with a message under the field; as Viewer the same screen is read-only; `/` opens the Worker Directory.

## Rules

| # | Rule |
|---|------|
| W1 | Worker: `workerCode` 1-20 chars `[A-Za-z0-9_-]`, unique case-insensitively · `fullName` 1-120 (trimmed, not blank) · `designation` 1-80 (free text) · `hourlyRate` > 0, ≤ 999.99, at most 2 decimal places · `isActive` |
| W2 | Reads (`AnyUser`): `GET /api/workers?includeInactive=false` (ordered by code, active only by default), `GET /api/workers/{id}`, `GET /api/workers/next-code` → `{ workerCode }`: `EMP-` + (highest numeric suffix among codes matching `^EMP-\d+$`) + 1, zero-padded to at least 3 digits, never an existing code; `EMP-001` when none. Writes (`HrOrAdmin`): `POST /api/workers` → 201 + worker; `PUT /api/workers/{id}` (all four editable fields, code included, uniqueness re-checked) → 200 + worker; `POST /api/workers/{id}/deactivate` and `/activate` → 200 + worker (idempotent); `DELETE /api/workers/{id}` → 204. Unknown id → 404 |
| W3 | Validation failures → 400 `ValidationProblemDetails`, camelCase keys `workerCode`, `fullName`, `designation`, `hourlyRate`. A duplicate code (also when two requests race: catch the unique-index violation, SQL error 2601/2627) → 400 with `errors.workerCode = ["Worker ID already exists."]` |
| W4 | Delete is a hard delete. If the worker is referenced by other records (foreign key violation, SQL error 547 — attendance, leave and payroll tables arrive in later slices with `ON DELETE RESTRICT`) → 409 problem "This worker has records and cannot be deleted. Deactivate the worker instead." No history table exists yet, so this path is covered by a test in S3 when Attendance is added; build the mapping now |
| W5 | Audit (via `IAuditLogger`, saved in the same `SaveChangesAsync`): `WorkerCreated`, `WorkerUpdated` (details: only the changed fields as `{field: {old, new}}`; a rate change is always visible there), `WorkerDeactivated`, `WorkerActivated`, `WorkerDeleted` (details: code and name). `EntityType` = `Worker`, `EntityId` = worker id. No audit row when an update changes nothing |
| W6 | `PayrollSettings`: single row (`Id = 1`, CHECK `Id = 1`) seeded by the migration with: CompanyName `DE AKS BE GLASS & ALUMINIUM CO. L.L.C S.O.C`, Tagline `Glass & Aluminum Installation & Maintenance Services`, ContactEmail `hr@dxbaluminium.ae`, OvertimeRatePerHour `2.22`, MaxBasicHoursPerDay `8`, ShiftDescription `06:00 AM - 05:30 PM`, PreparedByLabel `HR Department`, ApprovedByLabel `General Manager`. `GET /api/settings/payroll` (`AnyUser`) returns them camelCased. No write endpoint (the quote treats rule changes as change requests) |
| W7 | Viewer: all reads work, every write → 403; anonymous → 401 (secure-by-default already in place) |

## Data model

`Workers`: `Id` int identity · `WorkerCode` nvarchar(20) unique, `SQL_Latin1_General_CP1_CI_AS` · `FullName` nvarchar(120) · `Designation` nvarchar(80) · `HourlyRate` decimal(9,2) CHECK > 0 · `IsActive` bit default 1 · `CreatedUtc`, `UpdatedUtc` datetime2.
`PayrollSettings`: `Id` int PK (CHECK = 1) · `CompanyName` nvarchar(120) · `Tagline` nvarchar(200) · `ContactEmail` nvarchar(120) · `OvertimeRatePerHour` decimal(9,2) · `MaxBasicHoursPerDay` decimal(4,2) · `ShiftDescription` nvarchar(60) · `PreparedByLabel` nvarchar(60) · `ApprovedByLabel` nvarchar(60). One migration `AddWorkersAndPayrollSettings`, with the seed row inserted by the migration (`HasData`).

## API contract (used by the web task)

Worker JSON: `{ "id": 1, "workerCode": "EMP-001", "fullName": "...", "designation": "...", "hourlyRate": 12.5, "isActive": true }`. Create/update body: `{ workerCode, fullName, designation, hourlyRate }`. Next code: `{ "workerCode": "EMP-005" }`. Problem bodies as in S0/S1 (`title`, `status`, optional `errors`). Settings: `{ companyName, tagline, contactEmail, overtimeRatePerHour, maxBasicHoursPerDay, shiftDescription, preparedByLabel, approvedByLabel }`.
